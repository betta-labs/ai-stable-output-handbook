# 案例写作模板

本模板用于撰写企业 AI 落地公开案例。复制以下结构到新文件中，按提示填写。每个案例必须包含来源标注、可确认事实、控制启示和不可外推事项四个核心部分。

## 文件命名

```
cases/<vendor>-<organization>-<scenario>.md
```

示例：
- `cases/openai-morgan-stanley-knowledge-assistant.md`
- `cases/anthropic-legal-ai.md`
- `cases/openai-customer-support.md`

## 模板正文

```markdown
---
title: <组织名>：<场景简述>
description: <一句话概述：什么组织、什么场景、来源类型、核心控制启示>
editLink: false

> **厂商 / 模型：** <OpenAI / Anthropic / 其他 / 未披露>
```

## 写作检查清单

提交前逐项确认：

- [ ] **来源可定位**：每个事实都有 URL + 发布日期 + 来源机构
- [ ] **区分"当事方称"与"已查证"**：自述数字不写成已验证结论
- [ ] **标注时间**：来源日期、信息有效期
- [ ] **标注适用范围**：行业、地区、业务场景的边界
- [ ] **不可外推事项**：至少 3 条，明确说明什么不能推导
- [ ] **控制启示具体**：不是"要重视质量"，而是"在哪个环节、用什么机制控制"
- [ ] **不编造数字**：没有来源的数字不写，标注"待补充"
- [ ] **不推荐产品**：案例是控制学习，不是厂商推荐
- [ ] **description 唯一**：frontmatter 的 description 不与其他页面重复

## 来源等级说明

| 等级 | 类型 | 可信度 | 使用方式 |
| --- | --- | --- | --- |
| A | 监管裁决 / 法院判决 / 官方调查 | 高 | 可直接引用事实，仍需标注辖区和时间 |
| B | 独立调查报道（多方信源） | 中高 | 引用时标注"据报道"，注意未回应置评的部分 |
| C | 当事方自述（官网 / 博客 / 新闻稿） | 中 | 标注"当事方称"，效率/采用率数据需打折 |
| D | 单一来源 / 未验证传闻 | 低 | 不单独作为事实依据，可作为线索待验证 |

## 与第 16 章的关系

- 第 16 章的公开案例表是**精选摘要**，用于手册正文
- 本案例库是**完整档案**，每个案例有独立页面和详细分析
- 新增案例先在本案例库建立完整页面，再决定是否摘要进入第 16 章
- 第 16 章的案例卡应链接到本案例库的对应完整页面
