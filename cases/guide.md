# 案例与证据阅读指南

本手册不把"看起来可信的故事"当成企业效果承诺。不同材料承担不同证明责任；只有先辨认材料类型，案例才可以被负责任地使用。

## 四类材料的边界

| 材料类型 | 可以回答什么 | 不可以据此推断什么 | 阅读入口 |
| --- | --- | --- | --- |
| 公开案例 | 其他组织公开披露了什么、边界是什么。 | 你的组织会获得相同效果。 | [案例库](./) · [第 16 章](../16-第16章-完整案例集.md) · [附录 D](../20-附录D-资料出处与延伸阅读.md) |
| 教学情景 | 如何使用模板、控制点和回退逻辑。 | 它是事实记录或外部基准。 | [第 16 章](../16-第16章-完整案例集.md) |
| 受控运行证据 | 在明确范围内已记录了哪些试点观察。 | 未覆盖场景同样已被生产验收。 | [P2 试点证据包](../evidence/README.md) |
| 动态事实卡 | 某模型或工具在特定日期的可复核信息。 | 信息在未来仍然有效。 | [事实卡登记册](../facts/模型与工具动态事实卡登记册.md) |

## 公开案例的使用原则

### 1. 只提取可确认的有限事实

每个案例只写来源明确记载的内容。当事方自述的采用率、效率提升、成本节约等数字，标注为"当事方称"，不作为已验证结论。

### 2. 标注来源等级

- **监管裁决 / 官方文件**：可复核的法律或行政记录
- **独立调查报道**：多方信源交叉验证的新闻报道
- **当事方自述**：官方博客、新闻稿、案例页面（需打折阅读）
- **多方交叉验证**：两个以上独立来源确认的事实

### 3. 明确不可外推事项

每个案例必须说明：什么不能从这个案例推导出来。例如：
- "不是全球通用的法律规则"
- "当事方的效率数据不能作为其他企业的目标"
- "'适用于'不等于每个领域都已生产运行"

### 4. 借鉴控制逻辑，不复制数字

案例的价值在于展示"什么控制是必要的"，而不在于"他们获得了多少提升"。请关注：
- 他们选择了什么场景、回避了什么场景
- 他们如何定义任务边界和质量标准
- 他们如何处理知识来源、人工审核和回退
- 他们在什么条件下才扩大范围

## 教学情景的使用原则

教学情景是为了演练控制资产而设计的抽象场景，不对应任何真实组织。使用教学情景时：

- 关注"如何填写模板、如何识别控制缺口"，而非"这个场景的结果"
- 教学情景中的组织名、数据、比例均为虚构或去标识化
- 不要把教学情景中的步骤直接复制到生产环境
- 真实项目应使用 `evidence/` 目录和附录 A、B 的资产记录实际样本

## 受控运行证据的使用原则

受控运行证据（如 P2 试点证据包）记录的是在明确范围内的试点观察。使用时：

- 只在证据声明的范围内引用结论
- 注意"待现场验证"标记——这些项目尚未完成
- 证据包中的设计文档不等于运行结果
- 扩大范围前必须完成证据包中列出的未验证项目

## 动态事实卡的使用原则

模型和工具的能力、价格、限制会随时间变化。事实卡记录的是特定日期的信息：

- 引用事实卡时必须标注日期
- 决策前应核实信息是否仍然有效
- 事实卡不构成对模型或工具的推荐
- 不同事实卡之间的比较需注意评测口径差异

## 如何补充或修订案例

如果你希望补充案例或修订事实，请优先提交：

1. 可定位来源（URL + 发布日期 + 来源类型）
2. 适用范围和不可外推事项
3. 反例或限制条件（而不只是"效果很好"的结论）
4. 与现有案例的关系（补充 / 修正 / 矛盾）

提交前请自查：是否区分了"当事方称"与"已查证"？是否标注了时间和适用范围？是否避免了把单一案例当成通用结论？
