# 维护节奏与质量门

**用途：** 将《企业 AI 稳定产出手册》从一次性文稿转为持续维护的公开方法资产。本文件定义事实、案例、章节、模板、入口页面和站点发布的最低维护节奏；不要求每次复核都发布新版本，但要求任何重要变更可追溯。

**维护原则：** 不以新增页数、案例数量、工具数量或模型热点作为质量指标。优先修正失效事实、控制边界、读者行动路径和模板可填写性；关键行动还应能回答“谁判断、依据什么、记录什么、缺什么就停止”，指标应说明可能误读与反证条件。低风险探索与受控运行必须区分：不让完整生产资产阻断可逆学习，也不让临时探索绕过真实工作所需的权限、审核与回退。只有已有章节、附录、事实卡、案例卡或专题页均无法承载的新问题，才讨论结构性调整。

## 一、维护对象与默认责任

| 对象 | 默认维护责任 | 最低复核触发器 | 记录位置 |
| --- | --- | --- | --- |
| 核心主张、阶段闸门、风险边界、入口职责 | 手册维护 Owner | 改动开篇、README、高管摘要、快速开始、`start.md` 或首页时 | `核心决策内核.md` 与版本说明。 |
| 章节正文与交叉链接 | 对应章节 Owner；Owner 未指定时由手册维护 Owner 暂代 | 读者反馈指出重复/冲突；模板或案例变化影响章节时 | `章节职责卡.md`、变更记录与 Pull Request。 |
| 动态事实卡、工具/模型处理条件 | 事实 Owner；需时由技术/安全角色复核 | 官方政策、版本、端点、价格、数据处理条件或功能变化时 | `facts/` 与附录 D。 |
| 公开案例与教学情景 | 案例 Owner | 来源失效、发现关键新事实、案例被外推误读时 | 第 16 章、附录 D 与案例复核记录。 |
| 附录模板与 Practice Kit | 模板 Owner；至少一名第二使用者参与复核 | 教学演练失败、客户/读者反馈、章节或控制变化时 | 附录 A、资产登记与演练记录。 |
| 文档站、SEO、下载资产 | 站点 Owner | 每次发布前；构建/链接/路由变化时 | `pnpm verify`、站点脚本和发布记录。 |

## 二、月度轻量复核（30–60 分钟）

每月只处理最可能损害可信度的事项：

1. 运行 `pnpm lint:content`，修复本地链接、P0 一致性或内部质量规则失败。
2. 检查动态事实卡与附录 D 中本月可能失效的链接、政策、功能和案例来源；无法复核时降级措辞或标记待复核，不以猜测填补空白。
3. 汇总读者、内容评论、教学演练和项目复盘中的高频问题；将其归入现有章节职责，而不是立刻新增章节。
4. 检查至少一个高频模板是否仍能由第二使用者独立填写；若不能，记录具体阻塞、修订人和下次复测日期。首次使用路径优先抽查 L0 三项是否能让读者找到“立项—任务定义—验证与回退”，而不是要求其遍历全部模板。
5. 抽查本月新增或修改的一个关键行动、指标或角色描述：是否区分“今天可做 / 试点前必须有 / 不应单独决定”，是否保留探索/受控运行切换、四问、反证条件及替补/无权边界；若涉及优先级、扩展或激励，还应说明能力圈、机会成本、二阶影响、共享依赖和可能被奖励的错误行为。
6. 对第2章、第6章、模板入口或问题分流页发生的改动，检查首屏是否仍能让读者看见结论、可完成的产出和条件不足时的暂停/回退路径；不要以新增清单替代更清楚的入口。
7. 记录本月“修正 / 暂缓 / 无需动作”三类决定及其原因。

## 三、季度深度复核（半天）

每季度使用以下质量门，不以一次性全面重写为目标：

| 质量门 | 核心问题 | 通过证据 | 未通过时的动作 |
| --- | --- | --- | --- |
| 章节职责 | 每章是否仍只回答一个主要问题？ | 与`章节职责卡.md`一致；重复说明已压缩为链接。 | 合并/删减重复段落；不增加章节。 |
| 行动性 | 每章是否给出具体产出与下一步？ | 有可填写资产、Owner、证据或行动路由；第2、6章及模板入口能在首屏说明结论、最小产出和暂停/回退路径；关键控制点能回答四问，并区分使用者可做与组织授权决定。 | 补充任务入口或调整附录链接；不以更多抽象建议代替责任边界。 |
| 证据边界 | 事实、教学情景和受控证据是否清楚分层？ | 公开来源、非事实标识、不可外推说明或受控证据记录。 | 降级措辞、补来源或移出公开正文。 |
| 可复现性 | 模板是否能由非作者独立完成？ | 教学/受控演练记录与第二使用者反馈。 | 标记草稿，简化或重写模板。 |
| 运行适配 | 入口、指标、风险和阶段门是否仍互相一致？ | 核心决策内核、README、开篇、执行摘要、快速开始、`start.md`一致；探索与受控运行的切换条件清楚；指标有反证条件，角色有解释/阻断和替补边界。 | 先更新内核，再同步入口与附录模板。 |
| 维护性 | 事实卡、链接、版本和站点是否可持续维护？ | 月度记录、构建验证和责任人可定位。 | 降低无 Owner 内容的承诺或指定临时 Owner。 |

## 四、发布质量门

任何对外版本发布前，至少完成以下检查：

```text
内容与边界
- [ ] 新增或修改的事实均有来源、核验日期与适用边界；不确定内容已降级或删除。
- [ ] 教学情景显著标注为非企业事实；公开案例写明不可外推事项。
- [ ] 核心决策内核与章节职责卡已更新；入口页面没有另行定义冲突主张。
- [ ] 受控运行证据、客户资料、内部报价和未验证模板没有进入公开正文。

可执行性
- [ ] 变更涉及的模板、行动清单或交叉链接已由第二使用者或教学情景复核。
- [ ] 任何新增“扩大、上线、自动化、ROI”表述都指向相应证据、条件或暂停路径。
- [ ] 关键决定能说明谁判断、依据什么、记录什么、缺什么就停止；指标未把改善直接写成扩大结论。
- [ ] 业务 Owner、AI Champion、知识 Owner、技术/安全 Owner、FDE/AI COE（如适用）的决定权、替补和无权事项没有被混同。
- [ ] 新增探索、试用或Agent表述已说明其是探索轨还是受控运行轨；涉及真实受限数据、对外发送、写入、跨系统工具、持久记忆、多人复用或效果主张时，已补齐相称的切换条件与控制资产。
- [ ] 新增成本或规模化表述未将单次账单、节省工时或平均成本当作结论；已按单位任务、失败重试、人工接管和负载条件说明口径或边界。
- [ ] 修改第2章、第6章、模板入口或问题分流页时，首屏仍说明读者应得到的结论、最小行动产出与条件不足时的暂停/回退路径；L0三项不会被误读为高风险或生产运行授权。
- [ ] 新增用例排序、扩展或激励表述没有把固定加权分、调用量、登录次数、项目启动或演示效果写成充分结论；已检查能力圈、机会成本、二阶影响、耦合/单点故障与相称的证据更新。

工程与站点
- [ ] pnpm lint:content 通过。
- [ ] pnpm verify 通过。
- [ ] git diff --check 通过。
- [ ] 变更记录说明“改了什么、为什么改、哪些事实/边界受影响、下次何时复核”。
```

## 五、变更记录模板

```markdown
### YYYY-MM-DD｜变更标题

- **触发原因：** 事实变化 / 链接失效 / 教学演练 / 读者反馈 / 受控证据 / 编辑压缩。
- **影响范围：** 章节、附录、事实卡、案例、入口页或站点资产。
- **做出的决定：** 修正 / 扩大说明 / 缩小或降级措辞 / 暂缓 / 退役。
- **证据与边界：** 来源、演练记录、审批或不可外推说明。
- **判断与反证：** 谁作判断、依据什么、记录位置；哪些反证或缺失条件会触发缩小、转人工或暂停。
- **复核者：** 内容 Owner、事实/技术/业务复核者（按适用性填写）。
- **下次复核：** 日期或触发器。
```

## 六、首个90天维护实验

这套节奏在真实客户项目充分出现前，先以教学和内部演练验证：

1. 第一个月：选择会议纪要或客户回复教学情景，跑通“立项 → 任务 → 上下文 → 评测 → 回退 → 移交”的模板链；记录第二使用者的填写卡点。
2. 第二个月：针对一个真实但低风险、具备 Owner 与人审的内部工作流，收集有限范围的受控证据；不以结果宣传 ROI，也不承诺生产上线。
3. 第三个月：完成一次季度质量门复核，确定哪些表述、模板和案例需要修正，哪些可以保持，哪些应从公开材料中降级或退役。

> 手册成熟度的标志不是“覆盖更多热点”，而是每一次维护都能让读者更容易做出可验证、可暂停、有人负责的下一步决定。
