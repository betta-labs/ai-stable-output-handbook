# 核心决策内核

**用途：** 本文件是《企业 AI 稳定产出手册》公开入口页面的内部维护单一真源。它不替代正文，也不应被当作新的读者章节；README、开篇、高管执行摘要、角色化快速开始、`start.md` 与首页只能按目标读者压缩或链接本文件中的结论，不能另行定义相互冲突的核心主张、阶段闸门、风险边界或节奏。

**维护状态：** v0.1；每次改变公开入口中的核心判断、阶段门、风险等级、指标定义或默认阅读路径前，先更新本文件并在提交前运行 `pnpm lint:content`。

## 一、唯一的核心问题

在明确业务边界、人工责任和风险控制的前提下，如何让 AI 参与的工作产生**可复核、可维护、可接管**的结果。

这里的“稳定”不等于模型永不出错，也不等于调用量高。它要求结果能够定位到输入、来源、版本与验证记录；知识、上下文、工具与流程有明确 Owner 和更新责任；当输出、依赖或工具失效时，团队知道谁判断、如何暂停、怎样回退和恢复。

这里的“闭环”也不等于先建立一套固定、完整的生产流程。低风险、可逆的探索可以先验证任务、方法和上下文假设，但必须保留输入类别、禁止动作、时间/成本上限与下一步决定；当使用真实受限数据、对外发送、写入系统、跨系统调用工具、保留持久记忆、多人复用或主张效果时，必须切换到与风险相称的受控运行设计。

## 二、唯一的决策链

```text
业务目标与取舍
  → 问题/准备度诊断
  → 任务、工作流与上下文资产
  → 最小闭环、评测、人审与回退
  → 用例组合与自主性决策
  → 运行、韧性、安全与持续复盘
  → 能力移交、组织协同与退役
```

这不是 Prompt 到 Agent 的线性技术阶梯，也不是探索到治理的单向升级。提高自主性只有在任务更清楚、上下文更可靠、控制更完整、证据更充分时才成立；规则、固定工作流或已验证 Skill 能解决的问题，不应仅因技术潮流而升级为 Agent。受控运行发现目标、输入或价值假设不成立时，应能回到探索重新定义问题，而不是以更高自主性掩盖缺口。

## 三、核心术语与边界

| 术语 | 本手册的固定含义 | 不应被误读为 |
| --- | --- | --- |
| **公开案例** | 有可访问来源、只能支持来源记载的有限事实、必须声明不可外推边界的材料。 | 对其他企业的效果保证、采购建议或行业基准。 |
| **教学情景** | 为演练任务定义、风险、评测、发布、回退或移交而抽象化的示例，必须显著标明非企业事实。 | 真实客户案例、生产运行记录或收益承诺。 |
| **受控运行证据** | 在明确范围、样本、版本、审核、风险和验收边界下记录的实际项目材料。 | 通用的生产验收结论或对外宣传素材。 |
| **最小闭环** | 一个任务在受控范围内具备输入、输出、质量标准、样本、人审、回退和下一步决策的最小实验单元。 | Demo、单次 Prompt 成功或全量上线。 |
| **Agent** | 在受控权限与责任边界内编排已验证 Skill、上下文、记忆或工具的可选能力层。 | 所有企业 AI 场景的默认终点。 |
| **探索轨** | 在公开、合成、脱敏或已批准的有限材料上验证任务/方法假设的可逆学习活动；默认只读、草稿、沙箱或本地演算。 | 真实试点、生产运行、可以跳过数据与权限边界的豁免区。 |
| **受控运行轨** | 在真实工作中以明确 Owner、来源、权限、验证、接管与回退持续交付的活动。 | 低风险探索一开始就必须具备的全套生产资产。 |

### 行动与判断的固定表达

| 表达 | 本手册的固定含义 | 维护时必须避免的误读 |
| --- | --- | --- |
| **今天可做 / 试点前必须有 / 不应单独决定** | 将观察、记录、受控练习，与进入团队流程所需条件及组织授权决定分开。 | 把没有权限的使用者推去承担数据、对外、风险接受或生产决定。 |
| **谁判断、依据什么、记录什么、缺什么就停止** | 关键范围、质量、发布、异常与阶段决定应能回答这四问；答案可分布在立项卡、合约、评测或决策记录中。 | 为了表面完整新增冗余文档，或把“待确认”误读为默认继续。 |
| **指标反证** | 每个关键指标同时说明可能误读、即使改善仍应暂停的情形，以及解释/阻断分歧的角色。 | 把单一绿灯、平均值、调用量或沉没成本当作扩大理由。 |

## 四、阶段闸门与证据

| 阶段 | 最小进入条件 | 必须出现的证据 | 典型决策 |
| --- | --- | --- | --- |
| **探索** | 有明确学习问题、有限输入类别、禁止动作和时间/成本上限；不影响真实业务。 | 探索记录：假设、尝试、失败/惊喜与下一步决定。 | 转为候选、继续小范围探索或停止。 |
| **候选** | 业务问题真实，有业务 Owner，愿意说明不做什么。 | 用例立项卡与初始风险初筛。 | 启动设计、暂缓或不做。 |
| **试点** | 任务边界、数据获取、失败成本和人工责任可说明。 | 最小闭环运行记录、样本与验证清单。 | 修复、限量运行或停止。 |
| **限量运行** | 质量、采用、成本与回退达到项目自定义阈值。 | Golden Set、回归、发布登记与人工接管记录。 | 扩大范围或继续观察。 |
| **受控生产** | 责任、版本、知识、评测和运行控制持续有效。 | 健康卡、运行记录和组合台账。 | 维持、改进或降级。 |
| **规模化** | 第二团队可以在既定控制下独立运行维护。 | 移交清单与接棒验证。 | 跨团队复制或暂缓。 |
| **退役** | 价值消失、风险不可接受或出现更合适替代方案。 | 退役记录与人工替代流程。 | 停止权限并归档资产。 |

阶段提升由业务价值、质量与采用、知识/数据、责任、回退和运行控制六类证据共同决定。每次阶段决定还应说明谁判断、依据什么、记录什么、缺什么就停止；任一关键条件不满足时，缩小、修复、暂停或退役均是正常决策。

## 五、入口页面的职责边界

| 页面 | 服务的读者问题 | 应提供的内容 | 不应重复承担的内容 |
| --- | --- | --- | --- |
| **README** | 这本手册解决什么，如何进入？ | 一句话主张、目录、默认阅读路径、来源与版本边界。 | 90 天行动细节、全部指标或逐角色清单。 |
| **开篇** | 为什么做、做什么、不做什么？ | 战略内核、取舍、风险偏好、预算与治理节奏。 | 单用例问题定位或具体试点设计。 |
| **第 2 章** | 这个团队/工作流现在卡在哪里？ | 单用例或团队准备度诊断和行动路由。 | 组织级业务组合战略。 |
| **高管执行摘要** | 管理者如何在 15 分钟内做投入与风险决策？ | 论点、阶段门、关键指标、签字责任和 90 天节奏。 | 完整方法解释或每周操作细节。 |
| **角色化快速开始** | 我这个角色本周、当月和当季做什么？ | 分角色行动清单与章节/模板链接。 | 重定义治理铁律、指标和阶段门。 |
| **`start.md` / 首页** | 我应该从哪个入口进入？ | 读者分流和下一步链接。 | 另写一套独立方法论。 |

## 六、变更与复核规则

1. 改动动态能力、价格、功能、政策、权限或数据处理结论时，先更新事实卡和附录 D，再修改正文。
2. 新增或调整案例时，先判断它属于公开案例、教学情景还是受控运行证据；不得以未标注材料填补真实案例空白。
3. 改动核心主张、阶段闸门、风险等级、90 天节奏或关键指标时，先更新本文件，再同步入口页面；同时核对行动分层、探索/受控运行轨切换、四问、指标反证和解释/阻断权限是否仍一致；提交前运行 `pnpm lint:content`、`pnpm verify` 和 `git diff --check`。
4. 每月复核链接、事实卡、案例边界和读者问题；每季度复核入口页面、模板可填写性、角色路线和章节职责。具体责任、质量门和变更记录格式见[维护节奏与质量门](维护节奏与质量门.md)。
5. 客户资料、未验证服务模板、内部报价、Bettagate 配置和运行日志不进入公开正文或公开 Practice Kit；对外案例须经过客户批准与去标识化审查。
